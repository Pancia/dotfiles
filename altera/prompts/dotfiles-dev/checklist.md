Each item is a mechanical rule that a brief, a spec or a change either keeps or breaks. Check every item against the document or the diff.

1. **Stale references.** Every `file:line`, file, function, flag and command the document names exists on `master`. Check each with `git show master:<path>` or `git grep -n <pattern> master`. A line number that has moved is corrected or removed; name the function as well, so the reference survives a later edit.
2. **Live files.** These paths go live on the operator's machine as soon as a change reaches the main checkout, with no install step: `rcs/` (hardlinked into `~` by `rcs/MANIFEST`), `services/*/*.plist` (loaded at the next fish start), `fish/functions/` and `fish/conf.d/` (linked into `~/.config/fish`), `lib/lua/seeds/` (Hammerspoon), `rcs/claude-settings.json` (every Claude Code session) and `ai/mods/` (hot-reloaded in every session). A brief or spec that changes one of them says so, and says how the operator checks the result. A change there that would break a shell start, a running service or every Claude session is BLOCKING.
3. **Public repo.** The repository is public. No secret, token, password, private host name, private file content, transcript quote or personal detail appears in code, tests, specs, briefs, reviews or worklogs. Private material belongs in `.cc/private/` (ignored by git) or the work-config vault (`~/Vaults/work-config`), never in a tracked file.
4. **Hermetic tests.** No test reads or writes the real `HOME`, live `~/.config`, `~/Library/LaunchAgents`, `~/.claude`, a live tmux server or a running service. Tests set `HOME` and any XDG variable to a temp folder. Git and jj run only in temp repositories with an explicit identity.
5. **How tests run.** Tests run with `uv run lib/python/run_tests.py <component or file>` from the worktree root, never with `cmds test` (it always tests `~/dotfiles`) and never with a bare `pytest`. A new test folder is registered in `COMPONENTS` in `lib/python/run_tests.py`, or it never runs.
6. **Mission size.** Each mission fits one worker in one sitting: at most 40 minutes. A larger one is split.
7. **One machine-checkable done check per mission.** Each mission has exactly one fenced `donecheck` block (strict JSON) with at least one `command` check. The `test` kind is Go-only: never use it here. A command check runs one test component or file, for example `uv run lib/python/run_tests.py bin/scratch/test_scratch.py`, not the whole suite. A done check is never written inside a markdown table.
8. **Fish.** A changed `.fish` file passes `fish -n` and keeps the gotchas in CLAUDE.md ("Fish Shell Gotchas").
9. **No `rm`.** No script, test or instruction deletes with `rm`. Use `trash`, or a temp folder that the test framework removes.
10. **Docs.** A change that alters behaviour a person or an agent relies on updates the matching doc in the same mission: CLAUDE.md, a `docs/` file or a skill under `ai/skills/`. A spec lists these under "Documentation Updates". A missing doc update for changed behaviour is BLOCKING in a merge review.
